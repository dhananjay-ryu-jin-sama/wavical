# Wavical AI Privacy & Data Handling Policy

This document defines the privacy guarantees, data lifecycle, local storage locations, network transmission boundaries, logging policies, index encryption status, and model licensing responsibilities for Wavical Phase 3 AI-Native Infrastructure.

---

## 1. What Is Stored Locally and Where

All local AI storage is partitioned strictly by user and application ID under standard OS application data paths.

On Windows, the root directory is located at `%LOCALAPPDATA%\wavical\` (or `%APPDATA%\wavical\`):

| Component | Path | Description & Contents |
|---|---|---|
| **Engine Binaries** | `%LOCALAPPDATA%\wavical\cache\engines\<engine-id>\` | Downloaded inference engine executables (`llama-server.exe`), verified against catalog SHA-256 hashes. |
| **Model Weights** | `%LOCALAPPDATA%\wavical\cache\models\<model-id>\` | GGUF model files (e.g. `qwen2.5-1.5b-instruct.Q4_K_M.gguf`), verified against catalog SHA-256 hashes. |
| **Vector Index & Embeddings** | `%LOCALAPPDATA%\wavical\apps\<appId>\data\ai\index.sqlite3` | SQLite database storing collections, document chunks, metadata, and 384-dimensional dense vector embeddings generated by the embedding model. |
| **Cloud Consent State** | `%LOCALAPPDATA%\wavical\apps\<appId>\consent.json` | JSON store recording whether the user approved cloud transmission for a specific host (`{ "<host>": true }`). |
| **Catalog Cache** | `%LOCALAPPDATA%\wavical\cache\catalog.json` | Cached verified model catalog metadata (names, URLs, checksums, parameter sizes). |
| **Cloud Secrets** | Windows Credential Manager | API keys set via `wavical secret set <host>`, stored securely by the OS under target `wavical:<host>`. |

## 2. What Can Leave the Machine and When

Wavical enforces deterministic data boundary guarantees depending on the configured `ai.mode`:

### Mode A: `local` (Default)
- **Zero Network Transmission**: When `ai.mode` is `"local"`, no user prompts, document texts, chunk contents, embeddings, or metadata ever leave the local machine.
- No network socket is opened to external servers for inference. The local engine communicates exclusively over the loopback interface (`127.0.0.1`) on ephemeral ports.
- Local mode functions completely offline without an active internet connection (after initial model download).

### Mode B: `cloud`
- Text is transmitted to the remote API host specified in `ai.cloud.baseUrl` (e.g. `api.openai.com`).
- **Mandatory Native Consent Dialog**: Before the first request is sent to any cloud provider, Wavical prompts the user with a native OS dialog naming the exact remote host and stating that input text will be sent to that service. If the user declines, the request is aborted and no data is sent.
- **Strict Host Pinning**: Requests are only sent to the specific host in `baseUrl`. Cross-host redirects are rejected.
- **TLS & Certificate Verification**: All cloud connections require HTTPS with strict certificate verification (`rustls-platform-verifier`). Certificate checks cannot be disabled.

### Mode C: `local-first`
- Attempts local execution first. If the local engine is unavailable or unconfigured, falls back to the cloud provider under the exact same consent, TLS, and credential rules as `cloud` mode.

## 3. What Is Logged

Wavical follows strict data minimization and secret sanitization in its structured logging:

1. **Prompt & Completion Text**:
   - In production releases, prompt texts and completion outputs are **NEVER** logged to log files or standard output.
   - In debug tracing, message content is truncated to at most 64 bytes on valid UTF-8 boundaries to prevent memory bloat and unintended logging of sensitive data.

2. **Credentials & Secrets**:
   - API keys are stored in `Zeroizing<String>` wrappers that zero out memory on drop.
   - Secret types implement custom `Debug` and `Display` traits that output `[REDACTED]`.
   - API keys are never written to log files, error messages, terminal output, or IPC responses.

3. **Metrics & Performance**:
   - Latency, token counts, model identifiers, chunk counts, and collection names may be logged for operational observability without including raw document text.

## 4. Index Storage Security Notice (Unencrypted at Rest)

> [!WARNING]
> **Semantic vector indexes (`index.sqlite3`) are NOT encrypted at rest by Wavical.**
> - Document chunks, text excerpts, metadata fields, and vector embeddings are stored in standard SQLite format within the user's local application data folder.
> - Protection at rest relies entirely on OS-level file permissions and whole-disk encryption (such as Windows BitLocker).
> - If an application indexes highly sensitive or classified data, developers must ensure that the host machine utilizes OS-level disk encryption.

## 5. Model License Responsibility Statement

Wavical provides tooling to download, run, and benchmark open-weights AI models from public catalogs and repositories. 

- **Developer & User Responsibility**: Different open models are subject to diverse upstream licensing terms (e.g., Apache 2.0, MIT, Llama Community License, Qwen License, DeepSeek License). Some licenses restrict commercial use, require attribution, or mandate specific usage guidelines.
- **No License Grant by Wavical**: Wavical does not grant, transfer, or alter upstream model licenses. Developers building applications with Wavical and end users downloading models are solely responsible for reviewing and complying with the respective licenses of each model utilized in their applications.
- **License Transparency**: Model catalog entries in Wavical include explicit `license` identifier fields and link to original source repositories to assist developers in audit and compliance verification.
